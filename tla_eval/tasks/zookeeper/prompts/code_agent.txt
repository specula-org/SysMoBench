## Modeling Requirements

### MANDATORY CORE ACTIONS (must include all):

1. **Election Notification** - Notification exchange between servers
   - Servers broadcast their votes (epoch, leader, zxid)
   - Servers receive and compare votes
   - Vote comparison based on: epoch > zxid > server_id

2. **State Transitions** - Server state changes
   - LOOKING: actively participating in election
   - FOLLOWING: accepted another server as leader
   - LEADING: won the election

3. **Vote Tracking** - Track received votes and determine quorum
   - Collect votes from other servers
   - Check if candidate has quorum (majority)

4. **Leader Selection** - Determine winner based on vote comparison
   - Higher epoch wins
   - If epoch equal, higher zxid wins
   - If zxid equal, higher server_id wins

### CRITICAL SEMANTIC DISTINCTION:

- **Fast Leader Election**: ZooKeeper's leader election algorithm
  * Each server proposes itself initially
  * Servers exchange votes and update based on comparison
  * Quorum-based decision (majority required)
  * Eventual convergence to single leader

- **Vote Comparison Logic**:
  * Compare (epoch, zxid, server_id) lexicographically
  * Higher values win
  * Ensures consistent leader selection

### MODELING REQUIREMENTS:

- Model each server's state (LOOKING/FOLLOWING/LEADING)
- Track current epoch and voted leader for each server
- Model notification message passing between servers
- Track vote counts for quorum calculation

### EXPLICITLY EXCLUDED (do not model):

- TCP/IP network details
- Message serialization format
- QuorumCnxManager implementation
- Thread synchronization details
- Actual data replication (focus on election only)

### REQUIRED BEHAVIORAL SCOPE:

- Model at least: Notification action for vote exchange
- Show election process from LOOKING to convergence
- Demonstrate quorum-based leader selection
- Include epoch advancement scenarios

### SPECIFICATION REQUIREMENTS:

1. **MUST include EXTENDS statement**: The specification must extend at least these modules: TLC, Sequences, SequencesExt, Naturals, FiniteSets, Bags
2. **TypeOK**: Define a TypeOK operator for type checking
3. **Spec Definition with Fairness**: The Spec definition MUST include appropriate fairness assumptions (WF_vars/SF_vars) to ensure liveness properties
4. **Next Operator Structure**: The 'Next' operator SHOULD be a disjunction of atomic actions
5. **DO NOT define invariants** (like LeaderUniqueness, etc.) - focus on modeling the system behavior
